# 小踏口吻口播文案生成器

把一个素材包（图片、链接、截图、零散笔记）变成小踏本人可以照着念的 3 分钟口播稿。

## 这个技能要产出什么

**只有口播正文。** 不要分镜、不要画面提示、不要括号里的动作说明、不要标题和章节小标题、不要"字数统计"表。用户拿到就是一段可以直接念的话。

唯一例外：正文里小踏本来就会说的东西——"先给大家看一张图"这种句子本身是口播内容，要保留。

## 先搞清楚"小踏"是谁在说话

这不是一个中立的解说员，是一个**有明确道德立场、替观众把话说完的人**。他的位置感是：

- 站在"普通人/孩子/被污名化的个体"这一侧，对着"系统性失职、审核链条、抢流量的媒体、拿了钱的人"开火。
- 情绪是**克制的愤怒**，不是煽动。他不动员、不喊口号，他做的是"把证据摆齐，然后问你，这正常吗"。
- 他常把自己放在观众里："我一开始也差点信了""咱们接着往下看"。他是替观众查证的人，不是权威。

违背这个位置感，稿子就会变成一个"客观报道"，那不是小踏。

## 工作流

### 第一步：把素材吃干净，建一份事实台账

用户可能给图片、链接、截图、文件。链接必须真的抓（web_fetch），图片必须真的看，不要根据文件名猜内容。图片的读法见下面"怎么读图"。 

边看边记下所有可以进稿子的**硬事实**：具体日期、具体金额、具体人名、书名/栏目名、原文引语、发帖平台。小踏的杀伤力全部来自这些细节——"花了将近100万""耶鲁大学东亚研究系""《中华上下五千年》注音美绘版""1年7个月翻译人民日报光明日报"。换成"大量资金""知名高校""一些童书"，稿子立刻失去力量。

同时标出**每个硬事实的来源**（哪张图、哪个链接）。后面如果用户问"这句哪来的"，要答得出来。

如果素材里出现**互相矛盾**的信息，或者某条关键事实只有一个未核实的来源（比如某个小红书帖子），**不要当事实写**。小踏本人的题材里恰好在批这件事（见 `references/style-guide.md` 的"反转结构"），所以这种素材要么当"未核实的传闻"来写，要么直接弃用。

如果素材不足以支撑3分钟（硬事实少于5条），先告诉用户缺什么，问能否补充，而不是靠注水凑时长。

#### 怎么读图

**先试 `read_image`。** 如果模型支持图像输入，它会把原图直接给你看——这是最准的方式，版面、错字、画面里那个"不对劲的细节"都能一眼看到，而那个细节往往就是整期稿子的钩子。

如果 `read_image` 报 `does not declare image input`，说明当前模型不带视觉，改走 OCR：

1. `image_ocr`（**不要传 language 参数**——Windows 引擎在这类环境下带 language 会报错，不传反而能正确识别中文）
2. 如果 OCR 出来的内容是空的，但图明显是文字页，换 `engine: "paddle"` 或 `"rapid"` 重试
3. 如果图是照片、插画、界面而非文字，用 `image_scan` 看版面和区域，再用 `image_ocr` 配合 `region` 放大读关键文字

OCR 输出会在汉字之间插空格（"云 墨 视 觉"），读数字时还可能把 `47.6` 认成 `47 · 6`、把破折号认成"一"。**提取事实时要把这些噪声去掉再核对一遍**，尤其是金额、日期、人名——这些正是稿子里最需要准确的硬事实。

OCR 认不准关键数字时，**不要猜，但也不要去读素材的生成脚本、原始文件或任何"标准答案"来源**。那些东西可能对不上用户真正要你分析的那张图，而且会让稿子建立在一个用户看不见的假设上。宁可换引擎重试，或直接问用户那张图里写的是什么。写错一个金额，整期稿子的可信度就没了。

### 第二步：找到那条"认知落差"

这是整个稿子的发动机。小踏每一期都建立在同一个结构上：**一件事看起来是A，其实是B。**

- 案例一：教材配图看起来是"个别插画师审美翻车"，其实是"全品类全链条的系统性形象替换"。
- 案例二：一个美国青年看起来是"深深爱上中国的国际传播人才"，其实是"台湾防卫联盟实习过、做过开源情报分析的人"。
- 案例三：看起来是"伪史论者骚扰陕西文旅"，其实是"一条未经核实的小红书帖子走完了整个媒体链条"。

写稿前必须先能用一句话说出这条落差。说不出来，说明素材还没读透，不要动笔。

### 第三步：按骨架铺时间

3分钟 ≈ **950–1100字**（基准语速 323字/分，来自案例2的真实SRT：1172字 / 3分38秒）。完整骨架、每段的时间点和功能见 `references/structure-template.md`，动笔前读它。

骨架的五个部件，缺一个稿子就会散：

1. **钩子（0:00–0:20）** —— 直接从最扎眼的画面或最离谱的事实切入，**先别报名字**。案例2的第一句就是"甘肃敦煌一个县级融媒体中心"，报了名字才是第25秒。名字放得越晚，观众越走不掉。
2. **报名字 + 预告（0:20–0:32）** —— "大家好，我是小踏"，然后给一个承诺："今天这期视频你耐心看完，就知道……"。
3. **反转与展开（0:32–2:20）** —— 落差在这里揭开，然后用 2–3 组事实往上堆，一组比一组狠。
4. **升维（2:20–2:35）** —— 从这件事跳到它代表的东西，给出那句可以被截图的话。
5. **收尾（2:35–3:00）** —— "好了，这期视频就聊到这儿。我是小踏……一键三连"。

### 第四步：用小踏的话说，而不是用书面语写

写完初稿后，**逐句过一遍**，把书面语改回口语。这一步决定成败，不是润色。

判断标准很简单：**这句话你会对着镜头说出口吗？** "该事件反映出制度性缺陷"——不会。"所有环节都出问题——你管这叫什么？"——会。

必读：`references/style-guide.md`。里面是逐条的语言签名（短句断行、反问、"你品品"、同构排比、借他人之口、误引修复等）和**反面清单**（哪些词一出现就不是小踏了）。

**那个手册是招式库，不是必须全用一遍的清单。** 不要每期都套同一组招式，那会变成套路化的表演。只有两件事不能丢：**短句断行的节奏**，和**事实密度**。其余招式按素材的重心挑着用——素材不需要的招式，加上去只会有表演感。

要从案例里直接找手感，读 `references/samples/` 里的原始稿子。

### 第五步：自检（必做，不是可选）

稿子写完后**一定要**跑一遍机械检查，把文件先存下来再跑：

```bash
python scripts/check_script.py <稿子文件>
```

**这一步不能跳过。** 判据很硬：字数决定时长，时长是用户明确点名的要求。实测中"没跑自检"的稿子会超出 3 分钟窗口 30% 以上而无人察觉——写作者自己是感觉不出字数超了的。所以：跑它，按输出改，改完再跑一次，直到只剩你能解释的提示。

它会报字数/预估时长、平均句长、短句占比、签名句命中情况，并列出**过长行**和**书面语嫌疑词**。把长行改短，把书面语换掉。要理解每条指标背后的原因，看 `references/structure-template.md` 的"节奏指标"一节——指标只是把"听起来像不像"变成可以核对的东西，不是目的本身。

最后再读一遍全文，问自己三个问题：

- 观众在前20秒有没有被钉住？
- 我有没有在某个地方真的动了情绪，而不是全程一个调子？
- 有没有一句话，是观众会截图发出去的？

### 交付时

直接把口播正文给用户。**如果你把稿子存成文件，文件里也要只有正文**——不要因为"存成文件了"就顺手加上标题、时长说明、字数统计或分镜表。用户要的是能直接念的东西，加这些等于让他再去删一遍。

## 不能做的事

- **不要编造事实。** 人名、金额、机构、引语必须来自素材。素材里没有的，不写。这是这个技能的底线；小踏的题材本身就是关于"未经核实的信息被当成事实"，稿子自己犯这个错就彻底垮了。
- **不要中立化。** 不要写"对此，网友们看法不一"。小踏不搞平衡，他把证据摆完就下判断。
- **不要注水。** 时长不够就加事实密度，不要加形容词和"众所周知"。
- **不要用网络烂梗和书面套话。** 具体清单见 style-guide 的反面清单。
- **不要在正文外加说明。** 不要写"以下是口播稿"、不要写分镜、不要写创作思路、不要写字数统计。直接给正文。存成文件时同样只放正文。
- **不要在结尾复述。** 结尾是升维，不是把前面说过的再总结一遍——那是观众已经听过的东西。

## 目录

- `references/style-guide.md` —— 语言招式库与反面清单（**写稿必读**，按需取用）
- `references/structure-template.md` —— 3分钟时间轴骨架与节奏指标（**动笔前必读**）
- `references/samples/` —— 三个原始案例全文（找手感时读；案例2带真实SRT时间码，可用来核语速）
- `scripts/check_script.py` —— 机械自检
- `scripts/analyze_samples.py` —— 风格指标分析（新增案例时用来校准）
