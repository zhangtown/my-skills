# 投标文件合规审查

## 这个技能的分工

审查的对象是**别人写的或已经合稿的投标文件**，产出是一份能让商务/法人代表照着打钩的整改清单。

它的核心价值不在"找出一堆小毛病"，而在于**分诊**：把几十个发现压缩成"这几处不改就废标、那几处不改就丢分、剩下的是瑕疵可以放过"。因为一份终稿每改一个字都可能引入新错误，而且改动处还需要授权代表签字或盖章——改多了反而增加风险。

### 两种模式，边界完全不同

**先问清楚是哪种模式，不要自己假设。** 这两种模式的审查范围和"能不能动手改"差别很大。

| | 模式 A：技术标 | 模式 B：盖章签字前整体标书 |
|---|---|---|
| 何时用 | 技术标成稿、移交商务侧合稿**之前** | 商务技术合稿完成、打印签章**之前** |
| 范围 | 技术条款偏离表、供货一览表（品牌/型号/制造商/产地）、▲项证明材料、技术方案、服务承诺（售后/驻场/培训）、人员/业绩证明材料 | 全本 |
| 不碰 | 投标函、开标一览表、报价、分项报价、资格证明、营业执照、财务报表、纳税社保、法人授权委托书、保证金凭证、**商务条款偏离表** | 都是范围 |
| 主要产出 | ▲项材料清单核验 + 合稿前遗留项交接清单 | 逐页签章清单 + 文件外事项（密封/装订/份数/到账）打钩表 |

技术标阶段替商务侧填商务偏离表属于"画蛇添足"——一是越界，二是技术侧拿不到报价和主体信息，填出来的东西大概率要返工。合稿前把技术侧没做完的项列成**交接清单**交给商务侧，比替他做完更有用。

## 第一步：把招标文件的"尺子"取出来

不要凭印象审。先把招标文件里这几样东西**逐字**取出来，后面的判断全部引用它们：

1. **标记符号体系**。每家代理机构用的符号不一样，且**同一项目的不同采购包可能不同**。实测遇到过：包 1/包 3 用 `★`，包 2 用 `★`，包 4 用 `※`，包 6 **全文一个 `★` 都没有**。所以必须先探测本项目实际用的是哪个符号，再去数。`scripts/tender_scan.py` 会把 `★ ※ ▲ △ ◎ ◆` 逐个计数报出来。
2. **实质性要求的定义范围**。这是最容易被低估的一条。招标原文是：
   > 实质性要求是指本招标文件中用带星号（"★"）、"**必须**"或"**应（应当）**"等其他文字说明的商务和技术要求。如未按采购文件要求响应，按无效投标处理。

   也就是说，**"应"字句和"必须"句和 ★ 项是同一条红线**。一份标书里"应……"可能有几百处，真正需要逐条确认的是那些带具体要求的（"应提供加盖公章的 X 原件"、"应在 Y 天内…"）。
3. **无效投标情形清单**。通常在"投标人须知·符合性审查"一节，编号形如 `22.2.2`、`21.2.2`、`10.1/11.4`。见 `references/invalid-bid-clauses.md`，那里有跨项目归纳的通用清单。
4. **最高限价、保证金金额与形式、投标有效期、份数要求、异常低价三条线**。
5. **评标标准表（第三章）**——每一项分值、扣分规则、以及"证明材料"栏对材料形态的要求（第三方检验报告/产品说明书/产品彩页？复印件要不要盖章？）。
6. **第六章"投标文件格式及附件"的完整表单清单**，以及每张表的**栏目名称与顺序**、落款格式。招标若写了"请按照以下文件的要求格式、内容、**顺序**制作"，栏目错序就算偏离。

跑 `python scripts/tender_scan.py <招标文件>` 可一次拿到符号计数、废标条款、评分表文本和格式清单。

## 第二步：机读取证，不要只读文本

**纯文本审查会漏掉这轮审查里最致命的问题。** 以下每一项都必须落到文件结构层：

| 要查什么 | 为什么文本层查不到 | 工具 |
|---|---|---|
| 签章栏到底是"空文本"还是"有印章图片" | 公司名是**打字打上去的**，文本层看起来"填了"，但没有章 | `scripts/stamp_scan.py` |
| 每张图的**有效分辨率** | 图片像素够高但被文档缩放到很大 → 打印出来发虚；文本层看不到 | `scripts/img_dpi.py` |
| 文档属性里的真名、同源模板、编辑会话指纹 | 正文里干干净净，痕迹全在 metadata | `scripts/probe_docx.py` |
| 内部占位符 | `【待填】`、`【响应位置】`、`【待填·见批注】` 混在正文里，人工翻 400 页会漏 | `scripts/probe_docx.py` |
| 表格栏位错序 / 整行缺失 | 需逐表比对栏目名，人工只看到"有个表" | `scripts/probe_docx.py` |
| 图文对应关系（哪张图配哪条指标） | 需按段落顺序取"图 → 上下文"映射 | `scripts/img_dpi.py --map` |

`.docx` 本质是 zip，`word/document.xml` / `word/settings.xml` / `word/comments.xml` / `word/media/*` / `docProps/core.xml` 都是可解析的纯数据。先用 `probe_docx.py` 打一份全量 JSON 出来，后面所有判断都从 JSON 里查，比反复读文档快得多也准得多。

`.doc` 老格式先转：WPS COM 自动化比 antiword 可靠（antiword 对中文 GB 文档经常直接失败）。

## 第三步：六遍扫描

按这个顺序过，每遍只关注一件事，避免在细节里迷路。

### 第 1 遍 · 废标条款逐条对照
把第一步取出的无效投标情形做成表，**每一条都要给状态和依据**，不能写"未发现问题"了事。状态只有三种：通过 / 命中 / 无法从电子件核实（后者进"文件外待确认清单"）。

这一遍的重点是找**结构性缺失**：没有报价、没有开标一览表、资格证明不全、保证金凭证没附、有效期不足。

还要当心**工作副本陷阱**：同目录常常并存主标文件与「分项报价表 / 投标一览表」工作副本，填好的内容可能只在副本里，主标文件仍是招标原样空白表（实测踩过）。所以**每一份将被提交的文件都要各跑一次表格取值**，别只审那份填得最全的。

### 第 2 遍 · 表格与用语
- **填写用语必须用招标规定的词**。招标注里写"在'响应/偏离情况'栏填写'**响应**'、'**正偏离**'或者'**负偏离**'"，就**只能**用这三个词。实测有一份标书 67 行技术偏离表 + 13 行商务偏离表全部填"无偏离"（全文 79 处），招标从未定义过"无偏离"——虽然实务上多数评委认它是"响应"，但这属于零成本的确定性风险，一次查找替换就能消除。替换时注意别误伤本来就是"正偏离"的行。
- **栏目名称与顺序**逐一向招标模板对齐（实测踩过：业绩表把"合同金额"和"业主单位及联系电话"两栏顺序对调了）。
- **页码引用是否指向正确的材料**。▲项的"证明材料所在页码"如果只指向投标人自述的技术方案章节，评委按页码翻过去找不到第三方材料，该项就等于没证明。（实测踩过：12 项▲的页码全指向"4.3 技术能力"的自述章节，而彩页其实放在 5.1 节，只是没被引用。）
- **表格有没有被污染**：偏离表里混入评分索分文案（"可满足本项最高 2 分的评分要求"），这张表就不再是条款响应表了。
- **数字与编号一致性**：项目编号（含括号里的 SEU 编号）、日期、金额大小写、保证金数额、投标有效期天数、三处报价（开标一览表 / 附件 / 报价明细表）必须完全一致。

### 第 3 遍 · 证明材料（▲ 项的重点）
▲ 项**不是废标线，是扣分线**（常见每条扣 1.3–2.5 分），但它有一条隐藏的硬规定：**材料形态不符 = 即便功能真的满足，该项也拿不到分**。招标通常只认三种形态：**第三方机构检验报告 / 产品说明书 / 产品彩页**（复印件须加盖投标人公章）。投标人自述的技术方案**不算**。

逐项核验六件事，缺一不可：

1. **形态**：是招标认的那三种之一吗？
2. **齐备**：N 个▲项就有 N 份材料吗？招标要求的证明材料**逐项**提供，共用一张图是不行的。
3. **清晰度**：见下方专节。这是最容易翻车的一项。
4. **盖章**：复印件有没有加盖投标人公章？招标明写"如为复印件，需要加盖供应商公章"。
5. **对应关系**：图文对得上吗？有没有从别的章节复制错、两张▲项共用一张图、同一张图重复贴两次？
6. **数量级自洽**：指标说"不少于 20 个案例""不少于 60 个检测小类"，截图上真的数得出这么多吗？

#### 清晰度：算的是**有效 DPI**，不是文件像素

一张 4000×3000 的图被拉满整页，打印出来照样糊。真正决定可读性的是：

```
有效 DPI = 图片像素宽 ÷ 文档内的显示宽度（英寸）
         = 像素宽 ÷ (wp:extent 的 EMU 值 ÷ 360000 ÷ 2.54)
```

`wp:extent`（EMU；1 英寸 = 914400 EMU，1 cm = 360000 EMU）就是显示尺寸。`scripts/img_dpi.py` 会按段落顺序把每张图算出来。

**判读口径**（实测标定过）：

| 有效 DPI | 结论 |
|---|---|
| ≥ 300 | 印刷级，放心 |
| 200–300 | 良好，小字清楚 |
| 150–200 | 及格，正文字号正常 |
| 120–150 | **偏弱**——数字、英文、小号字会发虚，建议重出 |
| < 120 | **不合格**——评委核对可量化指标（"32 课时""≥60 个检测小类"）会很吃力 |

换算个更直观的：正文汉字原高约 13 px、显示宽 14.65 cm 时，打印后字高只有 **约 3.0 mm ≈ 8.4 pt**。

**补救优先级**：重新导出矢量（PDF / EMF）> 重新截图 ≥ 200 dpi > 原图放大（**基本无用，不要浪费时间**——放大不能凭空造出细节）。
另外：**只有"重出后 DPI 会真的提高"才值得重做**，先算一遍再决定要不要返工。

顺带把同文档内其它材料的 DPI 一起算出来做参照。同一份标书里，不同来源的材料 DPI 可能差一倍以上（实测：▲材料 111 dpi 垫底，业绩合同 284 dpi，证书类 206 dpi），这个对比本身就是最有说服力的论据。

#### 截图纪律
- **在白板版（无批注）的文件上截图**。带批注的版本截出来会把内部标注一起截进去。
- 输出规格：1920×1080、界面文字不模糊不重叠、符合企业级后台软件的视觉规范。
- 图下方配带域编号（SEQ 域）的图注。
- 截图必须和它证明的那条指标对得上——**从别的章节复制粘贴是最常见的错位来源**。

### 第 4 遍 · 文档痕迹（"电子表的个人痕迹"）
电子标时代，评标系统和外部质疑者都会看文件属性。**这一遍的目的是消除"同源"口实和隐私泄露**，不是找废标项——但一旦三家投标文件的属性交叉，前面所有技术独立性证据都作废。

| 查点 | 位置 | 实测踩过的坑 |
|---|---|---|
| 作者 / 最后修改者 / 公司 | `docProps/core.xml`、`docProps/app.xml` | 真名"凉月"从 v36 留到 v37 没人发现；两家陪标的 creator 与 lastModifiedBy 同为占位串「【待填：投标人全称-经办人姓名】」且 `revision` 都是 12 → 同源口实 |
| 编辑会话指纹（rsid） | `word/settings.xml` 的 `w:rsid` | 一份文件出现 1742 条 rsid（正常只有数十条）= 长期反复改稿，建议另存/清理后再出终稿 |
| 批注作者 | `word/comments.xml` 的 `w:author` | 三家必须互不相同 |
| 环境残留 | 全 XML | MAC 地址、硬盘序列号、用户路径（`C:\Users\<真名>\…`）、机器名 |
| **电子表格痕迹** | `.xlsx` 自身 | 隐藏工作表、单元格批注作者、共享工作簿修订记录、外部链接路径、数据透视缓存里残留的原始数据、自定义文档属性 |
| 内部占位符 | 正文 | `【待填】`、`【响应位置】`、`【待填·见批注】`、`[公司名]`、`XXX`。实测踩过：41 处`【响应位置】`占位符未填，而版本从 v36 到 v37 **只改了文档属性、正文一字未动** |
| 上传痕迹 | 标书之外 | 电子评标系统普遍记录上传 IP；投标文件的 MAC/硬盘序列号相同是被明文写入无效投标条款的 |

**多份文件同批投递时**（主标＋陪标），必须逐份比对上述字段的**两两交叉**，而不是只看单份是否干净。

### 第 5 遍 · 内容自相矛盾（失实陈述）
无效投标情形里有一条"提供虚假或失实资料的"，而且专门的条款会写"**一经查实作废标处理并没收投标保证金**"。找这类问题的方法是**交叉一致性**——同一个事实在文档不同位置的说法对不对得上。

实测抓到的三类：

1. **同一事项两页之内自相矛盾**。偏离表写"本项目投标标的所含节能类产品，属于最新一期《节能产品政府采购品目清单》范围内产品……我方持有节能产品认证证书"；而两页之外的节能产品信息表"归属编码"栏填的是"**无**"，并自注"服务器未列入清单"。这类问题一旦被评委翻到，援引的就是虚假材料条款，**不是扣分而是废标**。
2. **声称已做/已附但实际没有**。"已加盖单位公章"（没盖）、"另附《驻场服务承诺书》原件，随投标文件同步提交"（文件里没有这份独立文件）、"同时提供原件"（只有复印件）。
3. **响应与实物不符**。以"单盘容量高于要求"为由对接口/尺寸不符的配置声明"无偏离"；用"自研互连对标 2 条 UPI"这种口径置换替代"具备"；回避不写实际超标的功耗（TDP）指标。

**处理原则**：如实列示负偏离 > 修正措辞继续回避。主动声明一条负偏离通常只扣 0.2 分；被评委发现隐瞒，性质就变了。所以审查报告里遇到"技术指标确实不满足但标书声称满足"的，要明确建议改口径而不是帮忙圆。

### 第 6 遍 · 文件外事项
这些在电子文件里查不到，但每一条都是废标级。必须列成打钩清单让人到岗确认（见 `references/pre-sign-checklist.md`）。

至少覆盖：正本/副本份数与封面标注、签署盖章要求、装订方式、分袋密封与封口骑缝章、单独密封的开标一览表、电子版介质与文件格式、保证金到账与附言编号与系统内关联、授权代表能否到场、现场演示/答辩的时间地点与真实系统可跑状态。

## 第四步：分诊与报告

### 分级口径

- **P0 必废**：命中无效投标情形、实质性条款负偏离、缺必交文件、缺章缺签。不补不能交。
- **P1 丢分**：▲项材料形态/清晰度/盖章/对应关系缺陷、加分项材料缺失（节能/环境标志/政策扣除声明函）、栏目与用语不符。
- **P2 瑕疵**：栏目错序、措辞、编号不一致——改起来零成本但不改也不致命。

还有一类要单独标出来：**无法从电子件核实的**。这不是"没问题"，是"待确认"，必须单列。

### 报告结构

用固定的骨架，让人能扫读：

```markdown
# 投标文件风险审查报告 · <项目名>
<一行元信息：项目编号 / 代理 / 投标人 / 报价 / 投标截止 / 审查对象文件名 / 审查模式>

## 核心结论
<一句话说清：会不会废标、最大风险是什么、有无流标风险>

## 一、废标条款逐条对照
| # | 条款 | 要求 | 投标文件实际 | 判定 |

## 二、▲项证明材料核验
| ▲项 | 材料有无 | 形态 | 有效DPI | 盖章 | 图文对应 | 判定 |

## 三、格式与用语问题
## 四、文档痕迹问题
## 五、内容自相矛盾 / 失实陈述
## 六、签章清单（逐页）      <- 模式 B 的核心
## 七、文件外待确认事项（打钩表）
## 八、流标风险分析
## 九、整改优先级（P0/P1/P2）
## 附：审查方法与可复核依据
```

**结论区要给出量化判断**，不要只有形容词。写"▲材料 111 dpi 垫底、打印后汉字约 8.4 pt、建议重出"远胜"清晰度不足"。

### Word 版审查报告（交商务 / 法人代表 / 归档时）

Markdown 骨架是给自己看的；要交出去、要让人照着逐条打钩、要归档，就套**统一 Word 格式**出 `.docx`。格式已经固化成脚本，**不要把审查内容直接写进 docx 构建代码**：

```bash
bash scripts/report_docx/build.sh report.json "/abs/path/【审查报告】xxx.docx"
```

- 报告内容写成 JSON（块类型：`h1` / `h2` / `p` / `lead` / `quote` / `bullets` / `list` / `table` / `note`），格式由 `scripts/report_docx/report_style.js` 统一控制，改版式不动内容。**不要在新项目里现场再写一个构建脚本**——本管线就是从一份临时脚本（`create.js`）回灌而成的，等于把页码、目录域、底纹这些坑重踩一遍；有现成管线就直接喂 JSON。
- 完整样例见 `scripts/report_docx/example-report.json`（东南大学电力网络场景仿真项目·诚迈科技实战报告），照它抄最快。
- 版式要点：A4 · 页边距 2.54 cm · 正文宋体小四首行缩进 2 字符 · 标题黑体深墨蓝 · 页眉报告名 + 页脚居中页码 · **Word 原生目录域（打开后更新域即可）** · 表格浅蓝表头＋淡灰框线，**矛盾/风险行用 `highlight` 标砖红底纹**。
- 章节骨架与上面那张 Markdown 骨架**一一对应**，额外加封面页（标题 / 副标题 / 7 行元信息表）与目录。
- 按本技能纪律：**引招标或投标原文一律用 `quote` 块**（浅灰底纹），便于对方对照；分诊结论、页码定位、数字仍由审查过程负责，生成器只负责排版。
- **页码是报告里唯一的定位语言**：所有「位置：」都写被审文件的印刷页码（先建映射，基准写进附录），禁用段落序号 / 内部编号；报告自身目录页码在导 PDF 后回读校验（见 `references/report-docx-format.md` 第五节第 9–11 条）。
- 完整格式规范与踩过的坑（`PageNumber.CURRENT`、列宽归一化、目录更新域等）见 `references/report-docx-format.md`。

### 流标风险要单独算

招标文件通常设三道"不足三家"的闸口：投标截止后不足 3 家不得开标 → 通过资格审查或符合性审查不足 3 家废标。**所以"我方被废标"和"本项目流标"是两个不同量级的问题**——前者是自己出局，后者是整包重招。在陪标局里尤其要讲清：三家必须全部过审，任何一家被判无效就把有效家数减到 2，直接把项目拖成废标重招。

## 硬知识：本领域最容易翻车的十二条

这十二条都是真实踩过的，按"翻车概率 × 后果"排序。

1. **签章栏全是空文本**。标书里公司名是用字打上去的，一个真章都没有。实测有一份 226 页的标书 13 处签章位置**全部**为空（含投标函、开标一览表、报价明细表、各承诺函、偏离表、售后服务承诺书）。文本层看起来"填了公司名"，所以纯文本审查完全发现不了。结合"正本须经法人代表或授权代表签署并加盖公章，未按要求将被拒绝"，这是最典型的必废。
2. **法人授权委托书没章 = 其他章全白盖**。授权书上法定代表人没签章，签约代表在法律上就没有代表本项目的授权，投标函上任何"授权代表签字"都会落入"签字人无法定代表人的有效授权书"。**这张纸优先补**。
3. **《投标承诺书》是实质性条款**。招标格式注明确写"本'投标承诺书'为实质性条款，未按要求提供按无效投标处理"，而它的落款栏恰恰最容易被漏掉。
4. **"原件"要求**。"须提供加盖单位公章的驻场服务承诺书**原件**"、"无重大违法记录声明函**原件**"——彩色打印的复印件不算原件，且**必须是没有装在标书里的独立文件**还是随附装订，要看条款原文措辞。
5. **报价三处必须一致，且开标一览表要单独密封**。招标原文："《开标一览表》一式两份，一份装订在投标文件中，一份单独封装……如两份开标一览表中的投标报价不一致，视为提交备选投标报价，作**无效投标**处理"。另有条款写"如未单独封装或**未加盖单位公章**的，将作为无效投标处理"。
6. **不要直接拷贝招标文件的技术要求**。招标原文："供应商应逐一说明投标产品和服务响应，**直接拷贝招标文件技术要求的按照无效投标处理**"。所以偏离表里"投标文件技术指标情况"栏照抄招标原文 = 风险，必须是自己口径的复述。
7. **逐一说明品牌/型号/产地/技术参数**。招标原文："供应商应根据上表要求逐一说明投标货物名称、品牌、规格型号、产地、技术参数等，**否则，按照无效投标处理**"。实测踩过：核心产品的"生产企业名称/生产企业地址"栏为空。**另注意：换品牌/型号是连锁动作**——品牌一改，分项报价表「品牌 / 制造商、产地」、开标一览表政策栏、《中小企业声明函（货物）》、《关于符合本国产品标准的声明函》、《资格要求承诺函》（有没有写"不提供进口产品"）必须一起复核。第三方整机厂商多为大型企业，选它就等于放弃小微 10% 价格扣除，两处口径打架就是失实陈述（见例 5.7）。
8. **节能与环境标志认证：两张证书 + 两张信息表缺一不可**。详见下一节。
9. **异常低价三条线**。报价 < 全部通过符合性审查报价平均值×50%、< 次低报价×50%、< 最高限价×45% 三者任一即触发审查，现场限时（常见 30 分钟）提交成本测算，证明不了即无效投标。**报价前先算这三条线**。
10. **政策价格扣除是性价比最高的补分项**。《关于符合本国产品标准的声明函》+《成本比例声明函》（境内组件成本比例一般 ≥80%）对应 20% 价格扣除，《中小企业声明函》对应小微 10%——等于让对手打八折到九折。实测踩过：三家全部漏交。注意：**专门面向中小企业采购的项目，必须提供《中小企业声明函》，否则作无效投标处理**——此时它就从加分项变成废标项了。
11. **相同品牌按一家计算**。综合评分法下，提供相同品牌产品（非单一产品项目看**核心产品**品牌）且都通过审查的不同投标人，**按一家投标人计算**，只有得分最高的那个拿到中标候选人资格。所以陪标局的各家核心产品品牌必须互不相同。
12. **修改终稿会连带触发签章要求**。招标通常规定"改动处需由授权代表签名或加盖公章"。所以发现了拼写/用语类问题后要权衡：**要么每处签章，要么整表重排不留涂改痕迹**。这也是为什么审查报告必须分诊——把所有 P2 都改掉反而增加风险。

## 节能产品与环境标志产品（政府采购加分专章）

政府采购项目的评分表里通常各留 **1 分**给《节能产品政府采购品目清单》和《环境标志产品政府采购品目清单》产品。这 1+1 分看着小，但它有非常明确的判定路径，属于"能拿就该拿"的确定性分数。

**得分的完整链条（少任何一环都不得分）：**

1. 所投产品**落在最新一期品目清单范围内**——这一步是前提。不在清单内的产品，无论有多少证书都不加分。
2. 持有有效期内的**节能产品认证证书** / **环境标志产品认证证书**（节能证常见 CQC 编号，环境标志证常见 CEC 编号），且**证书有效期覆盖投标截止日**。
3. 提交评标办法要求的两张信息表：**《节能产品信息表》** 和 **《环境标志产品信息表》**。
4. 信息表里如实填写品目清单归属编码 / 品目名称 / 证书编号 / 有效期 / 型号，并与证书一致。
5. 在评标索引/响应对照表里标明所在页码，让评委翻得到。

**产品不在清单时怎么办**：如实填写"归属编码：无"，并在备注里说明该产品未列入清单。**不要为了拿分而谎称在清单内**——招标里有专门条款："供应商必须保证使用节能产品参加投标的真实性，如出现虚假响应，一经查实，将按照采购文件具体规定处理"，配合虚假材料条款就是废标。实测就抓到过这种自相矛盾（偏离表声称"属于清单范围内产品、持有认证证书"，信息表却填"无"并自注"服务器未列入清单"）。

**三个高频实操坑：**

- **证书被"清理"掉**。合稿时另一团队写的章节被整个删掉是常事，证书章节（如"环境标志产品认证证书""节能产品认证证书"两节）就在炮火范围内。**合稿后必须回头确认这些章节还在**。
- **制造商名称三个版本对不上**。证书上写"超云数字技术（南京）有限公司"、另一张证写"中电超云（南京）科技有限公司"、投标表里填"超云数字技术集团有限公司"（集团名）。这类不一致不影响证书有效性，但**建议补一句"证书所列制造商（含曾用名/关联主体）与本项目投标产品制造商为同一主体"**，并核对型号覆盖关系（如"R5210 G11 即证书所列 R5210"）。
- **清单版本必须是最新一期**。品目清单会更新，用旧清单对照会误判。

补分动作通常要**向厂商索取**（认证证书、盖章版规格书、原厂配置承诺函三件套），所以越早提出越好——从"发现缺材料"到"拿到证件"有采购部/厂商的响应周期。**设备选型阶段就该把"是否选用可加分的节能/环保型号"加进待办**，比递交前补救容易得多。

## 审查纪律

- **边界先确认**。技术标模式就只审技术标，不要顺手把商务侧的问题全列出来——那会让交接清单失去焦点。用户可以要求全量，但那是模式 B。
- **找到问题先汇报，不要直接改**。终稿改动有签章代价；而且用户对哪些是"必须改"、哪些是"授标策略选择"（比如报价区间、是否如实声明负偏离）有最终决定权。
- **不要为了好看而改**。纯排版美化不值得引入改字风险。
- **每一条发现都要给依据**：招标条款原文 + 投标文件页码/段落位置。没有依据的"建议"是噪音。
- **报告里的数字要能复算**。写出算法和取值（如 `639 px ÷ (14.65 cm ÷ 2.54) = 111 dpi`），而不是只给结论。
- **位置引用必须是对方能翻到的页码，不是一个口径一个数**。禁用段落序号 / 内部编号（实测：首版把 docx 段落序号 `P2717` 当位置写进报告，用户第一句就是「P2717 是什么鬼 哪有这么多页」）；先导 PDF 建「节标题 → 印刷页码」映射再动笔，页码基准写进附录，多页材料写区间。同一指标只留一个口径——换算法就全篇重算（实测：低清材料先报 5 张、重算是 7 张，三处同步改才自洽）。详见 `references/pitfall-library.md` 第 11.4 / 11.5 条。
- **抓不到证据就说抓不到**。"未发现支持串标的技术证据"是一个有价值的结论，但要同时说明真正的风险在场外（同机编制、同账户汇款、代理人同单位社保、上传 IP），不要因为稿件干净就让人放松。
- **同一份材料不要重复审**。第二遍复检时，先跟上一版报告做"已改/未改"对照表，把精力放在新引入的问题上——实测改版常常只改了文档属性而正文一字未动，也可能为了修 A 而压坏了 B。
